# Bounded active 3x Osc channel composer

This original channel owns its raw core and voices and connects prepared envelope/LFO modulation, the reachable type0 filter, release shaping, gain slew, voice accumulation, soft polyphony selection and completion notifications. It supplies a new C API; the native Fruity factory, editor and actual FL host scheduling remain separate gates.

`./reconstruction/plugins/generators/verify-channel.sh` builds a separate dylib and compares it against the installed original's actual factory, note trigger/release/kill, `ProcessEvent`, `NewTick` and `GenRender`. Original target/dependency SHA-256 values and a macOS arm64 compilation guard bind the fixed-offset helper calls. The rebuilt dylib links independently written source and Apple Accelerate. It does not load a commercial DSP library or embed captured code, assets or tables.

The corpus uses 180 original factories, each paired with one reconstructed channel. Raw waveform controls0..4, HQ/legacy, envelope flags0..31, enabled states, all three LFO shapes, curvature signs and depths vary. The volume envelope is enabled in every fixture. Ring/inversion/random-phase switches remain at their defaults; synchronized LFO flag32 and global113 are excluded. Rates and tempos are paired as 44100/60, 48000/90, 96000/120, 22050/137, 8000/240 and 384000/1000; each pair crosses explicit PPQs4/48/96/240/960/4096. Each context is fixed for the fixture. Dispatcher14 SetTimeSig receives the PPQ at Value+8; actual host time-signature/context delivery and tick scheduling are not reconstructed.

Each fixture performs 24 rounds, adding one or two notes per round, ordinarily releasing notes, occasionally repeating ordinary release or issuing a direct quick release, changing the signed soft limit -2/0/1/2/4/8/32, and rendering frame lengths1/2/3/7/8/9/15/16/63/441/1024/4096. Ordinary release enters envelope-release stages for groups1..4; the pan group0 remains untouched. Quick release from explicit requests or the soft limit preserves those envelope stages/positions and starts the declick position only if it was negative. Trigger selection prefers the last released voice at indices1..end, otherwise the first. Reaching the soft limit does not prevent adding another note.

Every trigger, release, render and removal is followed by comparison of voice-list counts and the exposed voice data:45 modulation words,112 filter bytes,two gains,three release fields,six raw phases,stereo flag and all40 borrowed parameter bytes. Final pan, volume, pitch[-2400,2400] and ModX/ModY[-.25,.25] vary per block. The caller restores each base final pitch before the original and model render mutate it in place. Nonzero1234.5 guards surround output. All compared output values must be finite.

The caller initially supplies varying nonzero output samples. The original's final write overwrites them with its internally cleared voice accumulator: native1bc640 calls a runtime pointer resolved to `ippsCopy_32f`, observed in the installed vector dependency at arm64 offset1c738. The model copies its accumulated voices over host output. Empty channel renders preserve host output and pending ticks. This is separate evidence beyond the earlier renderer corpora, which used only zero host destinations.

Completion notifications are emitted in current voice order as `VoiceKill(tag,-1)` and are compared with the original. The controlled callbacks record requests without reentrant mutations. The fixture sometimes retains completed voices for another block to compare repeated notifications, then explicitly removes them after render returns. Manual removal also occurs. Some fixtures destroy the model channel with voices still owned; native voices are explicitly killed first on that teardown branch, so this tests the new API's RAII cleanup and subsequent recreation, not identical original destruction ownership.

Five own-C-API rejection cases per fixture (zero/oversized frame count, unsupported global113, invalid final pitch and invalid trigger pitch) preserve output, notifications, voice data and borrowed parameters. These establish the new API's bounded rejection behavior; they do not compare invalid calls against the original ABI. Pointer lifetime, table content, output nonoverlap and nonthrowing callbacks remain caller preconditions. No injected allocation-failure/unwind or reentrant-host proof is claimed.

The release context is an actual initial44100Hz/441-sample table. The fixed type0 filter's activation, carried histories and cutoff slew are integrated. Source/math configuration stays fixed within a fixture, while per-note final levels change. Other filter modes, mid-note rate/tempo/PPQ or raw-control changes, synchronized LFO context registration, cross-channel global-context interactions, alternative raw oscillator modes, native object/factory/state/editor ABI, actual host notification timing, live application/project execution and complete Fruity/VST/AU equivalence remain open.
