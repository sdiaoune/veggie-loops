# Prepared active 3x Osc voice pipeline

This original composer connects coefficient preparation, five envelope/LFO groups, conditional ticks, oscillator rendering, the reachable single-pole filter, release shaping, gain slew and voice accumulation. It exposes a new C API and borrows the accepted raw core/voice. It does not provide the native Fruity factory or editor ABI.

`./reconstruction/plugins/generators/verify-prepared-voice.sh` builds a separate dylib from source and compares it with the installed original through its actual `CreatePlugInstance`, note trigger/release, `NewTick` and `GenRender` methods. Original images are checked by SHA-256 before loading. The harness refuses any architecture other than macOS arm64. Cocoa and Apple Accelerate are the only platform frameworks in the rebuilt code. No commercial library, asset, captured routine or wavetable is embedded in the rebuilt dylib.

The maintained corpus creates 360 original factories, each with two live voices, and renders 24 blocks per factory. It compares the complete stereo accumulator bit for bit, 45 modulation-state words, 112 filter-state bytes, two gains, release position/wait/flag, final pitch, six raw phase words and the stereo flag. Nonzero guards surround the initially cleared accumulator and are checked after each model voice and each original call. It also directly compares each original constructor's 441-sample release table with independently generated values. Voices are destroyed explicitly after each fixture.

Contexts use six fixed rate/tempo pairs: 44100/60, 48000/90, 96000/120, 22050/137, 8000/240 and 384000/1000. Each pair crosses six explicit PPQ settings: 4, 48, 96, 240, 960 and 4096. The original dispatcher14 is `FPD_SetTimeSig`; it reads `Value+8`, which matches the PPQ field of the SDK time-signature structure. This fixture supplies that field explicitly. Actual host time-signature/context delivery and tick production remain outside this test. Each fixture holds rate, tempo and PPQ fixed. Frame lengths are 1, 2, 3, 7, 8, 9, 15, 16, 63, 441, 1024 and 4096. Tick events are supplied explicitly, with periodic blocks having no new tick.

Raw oscillator controls vary across their observed musical ranges, waveform choices 0..4 and HQ/legacy paths. Random phase and inversion/ring switches stay at their defaults. Envelope fixtures vary enabled state, flags 0..31, delay/attack/hold/decay/sustain/release, curve signs, depths and all three LFO shapes. Synchronized LFO flag32 is excluded. Final pan, volume, pitch in [-2400,2400] and ModX/ModY in [-.25,.25] change between blocks. The base final pitch is reset by the caller before every render, matching the original's in-place modulation update. Release is exercised at blocks 6 and 13.

The native integrated editor's reachable default filter mode is type0. This composer preserves activation, cutoff slew and retained histories for that mode; it does not expose mode switching or the other separately verified prepared filter types. Global113 remains zero. Cutoff/resonance envelope/LFO depths are limited to [-32,32]; their combined normalized controls remain within the reviewed routing range. The new integration corpus also records finite working samples, output, carried histories and gains. These measured pipeline values extend the isolated primitives' smaller initial-state/sample/gain corpus; they do not prove arbitrary histories or arbitrary signal magnitudes.

Nine rejected scalar/configuration cases per voice preserve output, caller parameters, raw phases/stereo state, modulation state, filter state, gains and release state. Those checks establish this new C API's rejection behavior, not equivalence with invalid original ABI calls. Valid readable/writable pointers, table content and serialized borrowed-core access remain caller preconditions. Calls catch allocation failure in the composer, but there is no injected allocation-failure or unwind equivalence corpus. Three LFO tables contain 16384 finite samples in [-1,1] and outlive the voice. Legacy tables are configured before voice creation. All raw-engine instances must be serialized because factory/RNG state is shared.

The original constructor is tested at an initial 44100Hz context; its release table retains 441 samples after the explicit rate change. Other initial rates accepted by the new API are independent release-table generalizations. Other oscillator modes retain their separate raw-core proofs and are not extra evidence for this integrated pipeline. The original host pan callback is controlled, native host-kill callbacks are no-ops, voices accumulate in creation order into positive zero, and addition into preexisting host audio remains outside the API.

Native factory reconstruction, actual FL host time-signature/context delivery and tick production, synchronized LFOs, mode changes, voice stealing, host voice notifications, real state-stream/project execution, live application rendering, editor GUI and complete Fruity/VST/AU equivalence remain open. The compiler/native image bindings and measured counts are in `prepared-voice-verification.json`.
