# Bounded synchronized 3x Osc channel

This separate original channel connects the synchronized LFO metadata producer to raw oscillators, prepared five-group envelope/LFO modulation, the type0 filter, release shaping, gain slew, voice accumulation, soft polyphony selection and ordered completion notifications. It supplies a new C API. The accepted nonsynchronized channel and shared raw-core APIs stay separate; the native Fruity factory, editor and actual FL host scheduling remain unfinished.

`./reconstruction/plugins/generators/verify-synchronized-channel.sh` builds a distinct dylib and compares it against the installed original's actual factory, note methods, public control updates, `ProcessEvent`, `NewTick`, `SongPosChanged` and `GenRender`. The fixture verifies the original wrapper and engine/vector dependency hashes, and requires macOS arm64 before using native offsets. Rebuilt source links Apple Accelerate and independently written code, without commercial DSP libraries, captured code, assets or tables.

The corpus pairs 180 original factories with reconstructed channels. It varies deterministic oscillator waveforms 0..4, HQ/legacy, group raw flags 0..63, all three LFO shapes, curvature signs and depths. Public filter-mode parameter 113 stays 0, selecting type0. The internal dirty latch at configuration `+0x334` is distinct from that parameter at `+0x330`. The registry and pending/refresh metadata follow the separate [synchronized metadata contract](SYNC_LFO.md). Group writes and restore mark dirty; the next nonempty frame consumes it and rebuilds registration without resetting synchronized phases. Empty frames preserve metadata and host output.

The initial release context uses the actual 44100 Hz, 441-sample table. Current rate/tempo pairs are 44100/60, 48000/90, 96000/120, 22050/137, 8000/240 and 384000/1000, crossed with explicit PPQs 4/48/96/240/960/4096. Dispatcher 14 `FPD_SetTimeSig` receives PPQ at Value `+8`. Rate, tempo and PPQ remain fixed within each fixture. Ring, inversion and random-phase controls remain at defaults.

Each fixture runs 24 rounds with one or two new voices, ordinary/repeated release, occasional direct quick release and signed soft limits −2/0/1/2/4/8/32. Frame lengths are 1/2/3/7/8/9/15/16/63/441/1024/4096. A selected group's raw flag word changes every round, crossing the synchronized flag 32 while voices are alive. Volume-envelope enabled controls change after ordinary releases, exercising the native release-refresh branch: at `1bc530`, refresh plus volume stage 6 calls the envelope release helper again before ticking and rendering. The new channel applies that transition to its copied modulation state. The fixture separately counts pre-render stage6 candidates from the dirty/disabled-volume predicates; these are state observations, rather than instrumented function-call counts.

Ticks advance currently registered phases. Every third round, actual `SongPosChanged` dispatcher 13 requests controlled `FHD_GetMixingTime`/`GT_Ticks` data through the host callback. The delivered 16-byte pair's first double includes fractions, negatives, signed32 boundaries, 2^32 wraparound and supported finite values near signed64 limits. The new API validates finite [−2^63,2^63) inputs, then truncates and relocates phases through the same low32 modular product. Real application clock production and tick scheduling are outside this evidence.

After mutations, the fixture compares registry order/count/mask, all five synchronized phases and dirty/refresh/pending, followed by every live voice's 45 modulation words, 112 filter bytes, two gains, release metadata, six raw phases, stereo flag and all 40 borrowed parameter bytes. Final pan, volume, base pitch [−2400,2400] and ModX/ModY [−.25,.25] vary per block; the caller restores base final pitch before native/model rendering mutates it. Nonzero output guards remain intact. Both renderers overwrite varying nonzero host samples with their voice accumulation, and every audio float must match exactly and remain finite.

Completion notifications match the original's `VoiceKill(tag,-1)` order. Controlled nonthrowing callbacks record requests without mutating the channel. Some completed voices remain for another block to compare repeated notifications; deletion occurs explicitly after rendering. On the new API's live-channel destruction branch, the fixture first kills original voices explicitly. This proves the new channel's RAII ownership and subsequent recreation, not equivalent native destruction ownership.

Invalid new-API seek times, frame counts, unsupported filter mode and invalid pitches preserve the compared context/voice/parameter state, host output and notification lists. Invalid inputs are not sent to the native ABI. Allocation failures, callbacks that throw or mutate reentrantly, invalid pointer lifetimes and overlapping table/parameter/output storage remain outside the supported domain. All access is serialized across every raw-engine instance sharing factory/RNG state; tables contain 16384 readable finite samples in [−1,1].

This is bounded synchronized audio integration under supplied contexts. Live rate/tempo/PPQ changes, other filter modes, oscillator/custom/noise modes, cross-channel contexts, native object/factory/state/editor ABI, real host scheduling/project execution and complete Fruity/VST/AU equivalence remain open. The manifest binds exact source and artifact hashes and records the final native comparison counts.
