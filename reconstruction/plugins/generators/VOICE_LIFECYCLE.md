# 3x Osc voice lifecycle metadata

This small original source module reconstructs soft polyphony selection, quick-release metadata, prepared release-position advance and completion tests. It supplies a new C API. It does not implement the native note objects, envelopes, samples, factory or editor ABI, and it is not yet connected to the prepared voice composer.

`./reconstruction/plugins/generators/verify-voice-lifecycle.sh` compiles the helper dylib and replays its metadata rules against the installed original's actual factory, `ProcessEvent`, note trigger/release/kill, `NewTick` and `GenRender`. The target wrapper, oscillator engine and vector dependency hashes are checked before loading. Fixed entry offsets additionally require macOS arm64. The rebuilt dylib contains only the independently written metadata helpers.

Native `ProcessEvent1` stores the signed polyphony limit. Limits at or below zero disable it. When a positive limit is already reached, the next trigger marks one existing voice for quick release and still adds the new note. It falls back to the first voice; scanning indices1..end gives precedence to the last already released voice. A quick release sets the released flag and starts position0/wait0 only if the release position was negative. Repeating it preserves an existing position/wait value. It does not immediately delete the voice.

The maintained corpus uses 120 factories, default modulation/filter settings, HQ oscillator rendering, signed limits -2/0/1/2/4/8/32, two or more live notes, ordinary/repeated note releases, manual deletion, and deferred deletion after completion notifications. It verifies list counts, tags, released flags, release position/wait and actual original completion tests. Render lengths are 1, 7, 8, 63, 440, 441, 442 and 1024. Finished voices request `VoiceKill(tag,-1)` in current voice-list order. The controlled host shim records these requests and sometimes retains finished voices for another block, verifying repeated requests. Removal is performed explicitly after `GenRender` returns, preserving the original iteration.

A separate direct helper corpus uses live original editor objects with controlled release metadata: position -1/0/440/441/1024/INT_MAX-4096, wait 0/1/63/8192 and released0/1. It compares the compiled quick-release helper with native1bd320 and checks that all other bytes of the 416-byte editor object survive that call. Native1bd360 supplies the original completion predicate. Native1c3100 applies its actual precomputed release table to guarded temporary samples; the compiled metadata advance must match the resulting position/wait/flag. The original editor object's initial bytes are restored after these isolated calls. This is a controlled helper replay, not evidence that a live host produces arbitrary injected metadata.

The native initial release context remains 44100Hz with an actual 441-sample table. The module's generic completion length is a mathematical generalization beyond that factory corpus. Default disabled volume envelopes make ordinary release's metadata agree with quick release here; the different active-envelope state changes are explicitly outside this module's scope. Sample output is checked for finite values and intact guards, but this metadata fixture does not compare reconstructed audio. Audio/modulation/filter equivalence has separate maintained corpora.

The shim's queue, timing and deletion policy are synthetic. Actual FL host voice notifications, reentrant removal, scheduling, voice-object allocation/failure behavior, synchronized LFOs, dynamic contexts, editor, native factory ABI and complete Fruity/VST/AU equivalence remain open. All calls are serial with valid metadata/pointer storage; this thin helper API does not promise native invalid-call behavior.
